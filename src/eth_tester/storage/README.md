# ETH Tester — storage operational contract (B, Issue #2)

## Compatibility and migrations
`init_database(settings)` uses a dedicated database named `eth_tester` or `eth_tester_*`, checks the ownership marker or recognizes an existing legacy ETH schema, then runs checksum-pinned additive migrations. Never edit an applied migration; add a new migration. Unknown newer versions fail closed. `trades(symbol,trade_id)` retains global identity; converting this live table into a time-partitioned table would break existing `ON CONFLICT(symbol,trade_id)` callers. New archive-provenance and diagnostic event tables are month-partitioned; large legacy trade table conversion needs coordinated cutover.

## Transactional ingest / recovery
Use `storage.bulk.copy_trades(conn, rows)`, or for an existing COPY into temporary `eth_stage` use `storage.bulk.merge_staged_trades(conn, "eth_stage")`. Advance ingestion_job and ingestion_cursor in the **same transaction**. Differing canonical values for the same symbol/trade_id are rejected; identical replays are no-op, including concurrent conflicts through migration 0004. On exception roll back. After an actual worker stop, `storage.recovery.recover_abandoned_ingestion(conn,workers_stopped=True,stale_minutes=180)` requeues stale jobs without deleting rows; PostgreSQL WAL handles transactional crash recovery.

## Monitoring / deletion
`retention.storage_report(settings)` reports DB bytes and WAL LSN plus cluster-wide WAL generated bytes (cumulative) and optional on-disk WAL bytes (requires privileges). Estimated table counts avoid scanning billions of rows. `disk_guard(path,minimum_free_gb)` checks a **local** filesystem path; it must not be treated as the remote PostgreSQL host. `cleanup_diagnostics()` removes bounded batches only from diagnostic tables, never raw trades, candles or paper trades.

Backup: `backup_database(url,path)`, `backup_sha256(path)`, `verify_backup(path,expected_sha256=...)`, `restore_database(new_dedicated_url,path,expected_sha256=...)`. Restore always targets a **non-existing** dedicated database; failed restores remain for manual inspection. The backup's pg_restore table-of-contents verification is not proof of complete restorability until a test restore succeeds.

Delete: first call `deletion_manifest(url, backup_path)`. Then, only after human review, `drop_owned_database(url,confirmation=manifest["confirmation_phrase"],backup_path=backup_path,backup_sha=manifest["backup_sha256"],expected_database_oid=manifest["database_oid"])`. Requires exact ETH name, marker, OID, backup SHA and no connected sessions. **Drops one database only**, not shared PostgreSQL, files, other DBs or backup. Never wire to unauthenticated remote controls.

## Testing
`tests/test_storage_postgres.py` requires `ETH_TEST_PG_DSN` for a disposable server. It creates and cleans only fresh `eth_tester_ci_<uuid>` test databases. PostgreSQL 17/18 CI and real restored-data comparisons remain prerequisites for acceptance; `ETH_TEST_STORAGE_STRESS=1` enables 10,000-trade COPY stress. No real exchange orders.

Contracts: A Data — ingestion_coverage/trade_candle_volume_checks; C Analytics — level_events/analytics_cursor; F Learning — append-only causal feature_snapshots; E Simulation — paper_order_events/paper_funding_events/optimistic paper_position_state.


## Round 4: canonical snapshot provenance v2

Certified snapshots MUST be published through
`eth_tester.storage.snapshots.write_feature_snapshot(conn, ...)`.
Do not directly INSERT with quality='complete'/is_causal=true.
The API requires exactly the nine names in ml.FEATURE_NAMES. Each entry
in feature_sources has: source, instrument, interval (the empty archive
interval is VALID), checksum (64 lowercase SHA256), source_event_ms
(timestamp within ingestion_coverage event window), source_receipt_ms
(actual source receipt persisted in ingestion_coverage.evidence),
source_checked_at_ms (DB-persisted coverage check), coverage_status='verified',
and evidence_ref. The writer cross-verifies the event-time window, hash,
quality, checked_at and independently recorded receipt with DB rows and
pins a SHA256 of the witnessed evidence. It never considers a later source
availability timestamp to be inside an earlier archive event window.
For trades_archive only, CRC, identity and minute-volume evidence must
all be true; mere volume agreement does not certify all exchange prints.
Without actual independent evidence for L2/OI/levels/volatility, certification
fails CLOSED. The caller cannot assert valid coverage by setting booleans.

The writer's returned snapshot_key deterministically binds all nine
values and verified provenance. The PostgreSQL INSERT uses one DB
clock_timestamp() for available_at, observed_at and computed_at: all
three are real publication clocks, NEVER bar-close or retroactive receipt.
Feature source/event/receipt/check times remain separately visible inside
provenance and must precede publication. The writer emits
contract='eth_feature_snapshot_v2',
certified_by='independent_source_proof',
source_coverage_verified, coverage_status,
source_receipt_ms, source_checked_at_ms,
feature_available_ms and feature_sources. Non-certified snapshots stay
quality='partial_unverified', is_causal=false. Old v1 rows are not
silently upgraded. D/E/F still must independently validate this v2 contract,
as-of time, the exact snapshot_key/source_checksum and one position/$1000
paper limits; no real order routing.

## Round 4: independently evidenced post-horizon structural labels

Migration `0006_paper_ml_labels.sql` introduces
`paper_ml_labels` (NOT an entry-time change to paper_trades.reason).
`eth_tester.storage.labels.record_paper_ml_label(conn, ...)` accepts:
paper_trade_id, snapshot_key, source_checksum, outcome, horizon_end_at,
label_source, label_interval, covered_from_at, coverage_sha256,
source_receipt_at, coverage_checked_at, source_evidence and optional
label_instrument='linear'. It fixes method='fixed_horizon_barrier_v1'.
The PostgreSQL trigger rejects open trades, absent/tampered original
top-level reason.ml_snapshot_key/ml_source_checksum binding, snapshot
not available at the original decision, label issued before horizon
completion, and missing verified source coverage with exact DB-witnessed
receipt/checksum. It always sets issued_at using PostgreSQL clock_timestamp()
and forbids UPDATE and DELETE. The source_evidence must carry an
independently generated barrier_evidence_sha256. One row per trade is
allowed; replay of the identical label is idempotent, contradictory
replay fails closed. Training labels are NEVER derived from paper PnL,
and no model is promoted automatically.

The permanent marker, migration and table verification is available via
read-only database.verify_existing_schema(settings); normal supervisor
startup should use it under a limited DB role. Administrator applies
init_database and migrations explicitly. If absent or checksum-mismatched,
the supervisor must not spawn worker processes. Destructive DB/file
lifecycle remains gated by the original ownership/backup/OID protocol.

All PostgreSQL tests use randomized disposable test databases. Synthetic
source certificates in those tests demonstrate SQL contract compatibility,
NOT exchange-complete market evidence or production GO.


## Round 6 — two separate evidence systems, never interchangeable

**Historical/ML** remains strictly the existing immutable
`eth_feature_snapshot_v2` with nine independently witnessed proofs, real
publication clocks, exact original source digest, and certified_by
`independent_source_proof`. Historical archive gzip SHA + 1440 matching
minute base/quote totals are not an identity-complete exchange tape.
No code may promote `ingestion_coverage.status='partial'` to verified
merely because trade and candle volumes match. A's actual bounded live
observations are NOT eligible for F training, post-horizon ML labels or a
historical replay decision.

**Archive source membership** — new additive migration
`0007_bounded_live_and_archive_bins.sql` and B API
`storage.archive_receipts.persist_archive_stage_bins(
 conn,symbol,day,sha,expected_rows,stage_name='eth_stage')`.
Call inside A's existing transaction, after
`storage.bulk.merge_staged_trades`, while its validated
`pg_temp.eth_stage` still exists and before the ingestion-job cursor
is committed. The writer pins original gzip SHA and groups by
UTC minute / exact price / side. An archive trade initially received
over WS remains in the archive bins; a WS-only print absent from the
gzip is excluded. Replays of the SAME SHA compare ALL price bins
symmetrically and refuse conflicts; never silently overwrite provenance.
The C rollup MUST select only `archive_source_price_bins` joined on
actual `ingestion_job.sha256`, never global `trades` as if it were a
downloaded gzip. If B bins are absent, reject SHA-bound aggregation.

**Versioned revalidation:** `storage.archive_receipts.revalidate_archive_bins(
conn,symbol,day,sha)` reads original immutable bins and independently
closed official 1m candles, stores a new content-addressed
`archive_validation_receipts` result when the candle grid improves.
The original `archive_stage_receipts.captured_at` and first receipt
never change. The best possible status is `volume_only_reconciled`;
even perfect 1440-minute parity is NOT all-exchange trade-ID certification.
`archive_validation_receipts.exchange_complete` is always false.

**Bounded live paper evidence** is deliberately DIFFERENT:
`paper_live_evidence`, contract `eth_paper_live_evidence_v1`,
quality `live_observed_bounded`, `paper_only=true`,
`ml_eligible=false`, `exchange_complete=false`,
`is_ml_certified=false`. This matches D/E/H's already published
one-batch interface. A writes actual first WS receipts and book
snapshot/replay chronology through `storage.live_evidence.record_trade_receipts`
and `record_book_lineage`; A records independently received near-live
REST OI through `record_oi_observation` in the SAME transaction as
raw source rows. B source receipts and paper evidence are append-only.
C's source-triggered fast 1m path may call
`publish_bounded_paper_evidence(conn,symbol,bar_ts,trade_session,
book_receipt_id,oi_receipt_id)` only after original bybit_v5 CLOSED
1m candle, no overlapping unresolved WS/L2 interruptions, matching
observed ETH base + USDT quote, one actual WS session, fresh L2 replay
and observed 5m OI, all inside the original 90-second window.
The PostgreSQL trigger cross-checks underlying tables and sets
`observed_at=computed_at=clock_timestamp()` on INSERT. E/D require
actual independent paper decision time >= computed_at and <= expires_at.
A late source receipt cannot resurrect a historical signal or paper order.
`require_bounded_paper_evidence(conn,*,symbol,bar_ts,evidence_key,decision_at)`
reads and checks exact immutable key/source checksum/quality/clock without
converting live evidence to `eth_feature_snapshot_v2`. No exchange-wide
trade completeness assertion is made. F must skip all bounded-live paper rows.

**Post-horizon ML labels** — migration 0007 adds an independent INSERT
guard to existing 0006 append-only `paper_ml_labels`. Only E's
ORIGINAL precommitted historical-v2 label policy qualifies. F's
`full_future_grid` leaves original decision clock unrounded and
considers ONLY the next three entirely postdecision natural UTC minute
candles; the B guard rechecks grid and structural outcome against actual
persisted bybit_v5 closed OHLC. Both historical source receipt and
source coverage must be real, never inferred from paper PnL or caller flags.
All legacy labels stay untouched; old migrations remain checksum-pinned.

All included PostgreSQL tests use newly generated disposable
`eth_tester_...` databases and isolated synthetic fixtures to prove
SQL safety and contract compatibility ONLY. They cannot replace
actual Bybit observed source evidence, PG17/18 matrix PASS, native Windows
acceptance, or MASTER production GO. No trading API is used.


## Round 9: unattended paper-only storage maintenance

**Bounded diagnostic cleanup:** retention.cleanup_diagnostics(settings) remains
restricted to feed_health (90 days), bot_events (180 days), and
eth_storage_events (180 days), up to 10,000 rows per table per call. It uses
one transactional, nonblocking advisory cleanup lease; local lock_timeout
2500ms and statement_timeout 20000ms; FOR UPDATE SKIP LOCKED for diagnostic
rows. A competing maintenance run raises, not a false success. G may schedule
the existing CLI cleanup daily. The service DB role must have ONLY the
necessary scoped DELETE rights and ownership marker. The service may never
delete raw market sources, paper ledgers or historical ML evidence.

**Long-term research preservation:** bot_events records with
event='paper_trade_review_v1' or data.retention='preserve' are excluded
from the 180-day diagnostic purge. E must use this exact event name and
mark substantive paper review records. A bot_events entry is NOT an
append-only cryptographic ML certificate. Unbounded research will need a
future dedicated partitioned, protected research ledger and quota policy.

**Owned-temp cleanup:** optional ETH_TESTER_OWNED_TEMP_DIR must contain a
regular .eth-tester-owned-temp marker with exact content
eth_tester:temporary:v1 followed by newline. The sweeper removes at most
100 files per run, only old (>1h), regular, single-link, non-symlink files
named eth-tester-stage-<32 lowercase hex>.part. It never recurses or
touches backups, database directories, user files, young files, or raw
research data. A missing marker fails closed. No production source yet
emits this naming convention, so the sweep does not promise complete
orphan cleanup.

**Post-crash recovery:** storage.recovery.recover_abandoned_ingestion requires
an independently verified workers_stopped=True, and requeues only a bounded
batch of stale running ingestion jobs using its separate nonblocking
advisory lease, SKIP LOCKED and transaction-local statement/lock timeouts.
Default max 500, hard cap 5000. It never deletes archive rows or certifies
an interrupted import. PostgreSQL WAL handles transactional rollback; A
must retry the original immutable source SHA idempotently. Worker staleness
alone is insufficient to claim safe shutdown of a remote writer.

**Storage pressure:** storage_operational_preflight is read-only. It accepts
explicit database size and cluster-WAL thresholds, without assuming that
local disk free space equals the remote PostgreSQL server's free space.
When actual remote database disk capacity is unavailable, it reports
unknown, not ok. PostgreSQL WAL bytes are CLUSTER-wide, and permission to
read pg_ls_waldir() may be absent. The pressure report is diagnostic only:
it cannot authorize deletion of raw rows, or real orders.

**Backups and acceptance:** existing backup_database checks checksum and
pg_restore table-of-contents, not an actual restored-data comparison.
Real restore to a NEW dedicated disposable DB, full content/hash
comparison, power-loss injection, WAL pressure, least privilege,
service restart, Windows/Linux runtime and 24h public-feed soak remain
necessary for GO. tests/test_storage_round9.py models pure/fake-PG failures;
tests/integration/test_storage_round9_pg.py uses only a fresh random
eth_tester_b9_<UUID> disposable PostgreSQL test database, and has not yet
been executed in this B environment. All data are paper-only and synthetic.

## Round 11: source-state-safe retention and pinned-handle temporary cleanup

**Live admission and 90-day housekeeping:** `feed_health.topic='connection'`
is no longer automatically purged. A WS session may remain alive for over
90 days with no new connection event; deleting its latest 'connected' row
would cause B admission and Telegram health to lose the original session.
The full connection/disconnection ledger remains until a separately verified,
durable source-incident ledger and immutable retention policy exist.
No cleanup action certifies completeness of exchange trade IDs or resolves
`data_gaps`. The original protected `paper_trade_review_v1` and
`data.retention='preserve'` exclusions remain in effect. Ordinary diagnostic
events continue to be purged in bounded batches only.

**DB locks and cleanup result:** lock and statement timeouts are installed
before the ownership-marker query in both `cleanup_diagnostics` and
`recover_abandoned_ingestion`. A successful `cleanup_diagnostics` response
includes `status='ok'` (batch executed), `status_scope='batch_only'`,
and `cleanup_complete=false`: SKIP LOCKED can leave previously locked
eligible diagnostics and a 10k cap never establishes database emptiness.
It must not be interpreted as long-term readiness or trading permission.

**Filesystem race:** `storage.maintenance.cleanup_owned_temp` now operates
against a pinned POSIX directory descriptor with `O_NOFOLLOW`, validates
directory ownership and restrictive permissions and the exact single-link
marker through the same descriptor, and uses descriptor-relative stat/unlink.
The directory iterator is streaming and has a 10,000-entry scan budget,
preserving the maximum 100 deletions per invocation by default. Symlinks,
hardlinks, unexpected names, user backups, raw market data and research
files are not intentionally deleted. A swapped root path after validation
cannot redirect the cleanup to a different directory. **Windows fails
closed** until an independently verified native reparse/ACL/file-ID
implementation is available. On Windows leave
`ETH_TESTER_OWNED_TEMP_DIR` UNSET; do not enable automatic filesystem
sweep under LocalService.

**Operational qualification:** `tests/test_storage_round11_safety.py`
and `tests/test_storage_round11_retention.py` can execute in isolated
Python with fake PostgreSQL transactions. They do not establish SQL runtime
safety. `tests/integration/test_storage_round11_pg.py` requires real
PostgreSQL 17/18 and `ETH_TEST_PG_DSN`; each test provisions and destroys
ONLY a fresh uniquely named database. Exact 90+ day source continuity,
blocked ownership SELECT and competing cleanup lease are regression
assertions. Windows-native service, backup/restore, PostgreSQL disk
pressure, Telegram delivery and 24-hour public-data soak remain NO_GO
until separately exercised. Telegram persistent outbox design is not
implemented or certified in Round11.


## Round 14 — guarded POSIX backup and bounded temp preflight

All backup/verify/restore invocations **fail closed on Windows** and on POSIX
without /proc/self/fd and O_NOFOLLOW; native Windows file identity, ACL and
reparse safety are not yet implemented or qualified. This is a deliberate
availability limitation, not evidence of Windows support. There is NO fallback
to a writable PATH or bare pg_dump/pg_restore executable.

An operator must provision a verified, absolute, root- or service-owned
PostgreSQL client binary directory and set ETH_TESTER_PG_BIN_DIR to its path,
e.g. the actual PostgreSQL 17/18 native /usr/lib/postgresql/<version>/bin
directory. Tool binaries must be regular executable, not symlinks, and may not
be group/other writable. Each ancestor directory must satisfy owned/trusted
permissions; a root-owned sticky /tmp is an explicit exception. Do not use
a pg_wrapper symlink or insecure project virtualenv bin path.

The BACKUP DESTINATION PARENT must already exist, be owned by the current
service UID, have no group/other write permission, and have trusted ancestors.
No automatic mkdir of arbitrary user-provided backup paths is performed.
An exclusive random temporary archive is written there with 0600 permissions,
fsynced, sanity-checked using trusted pg_restore against a private pinned
snapshot, then linked to the final name without overwriting any existing
destination. Failed temp cleanup only unlinks a matching original inode;
foreign substituted file names are left intact. After final publication,
the parent directory is fsynced. A failure after publication is NOT proof of
rollback and must be checked by the operator.

For VERIFY and RESTORE the original archive file is opened O_NOFOLLOW,
copied from that pinned FD into a private 0700 folder, revalidated for source
identity, and kept open through both pg_restore --list and the actual
--single-transaction --exit-on-error restore. A sha256 mismatch or changed
private archive fails closed. pg_restore consumes /proc/self/fd/<fd> via
subprocess pass_fds, not a second open of a mutable user path. The restore
target must not exist; a failed restore is kept for explicit inspection.
After a completed restore, owner marker and schema migration checks run.

IMPORTANT: verifying a pg_restore table of contents and a SHA alone is **NOT**
a full restore/recovery attestation. The restored data, tables, receipts,
migration checksums, paper ledger, funded cash flow and operator-owned
backups must still be independently tested on genuine disposable PG17 and
PG18 before permitting destructive database deletion. A source archive is
not promoted to ML or funding certainty by backup verification.

The POSIX temp sweep now verifies the complete <=10000-entry directory
budget BEFORE any unlink, collects a bounded set of allowlisted old regular
file identities, and rechecks those identities immediately before deletion
using the same pinned directory descriptor. If the scan budget is exceeded,
the function raises with **zero deletes**; it cannot delete a few files and
then throw an unaccounted scan-limit error. Unexpected unlink failures report
how many files had already been deleted; even with inode checks, filesystem
operations are never advertised as crash-atomic. Keep G unattended cleanup
DISABLED until full OS/PG/24h evidence, and leave ETH_TESTER_OWNED_TEMP_DIR
UNSET on Windows.

Regression coverage: tests/test_storage_round14_published.py runs synthetic
POSIX filesystem/OS-subprocess tests and skips native Windows unsupported
paths; tests/test_storage_postgres.py requires a real disposable PostgreSQL
server (ETH_TEST_PG_DSN) and a trusted installed PG binary directory. A
skipped PG run is NOT an accepted backup/restore proof. This round contains
no DB schema migration and never authorizes real trading.
